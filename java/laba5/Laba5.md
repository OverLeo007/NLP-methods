# 1. Цель

Расширить семантический анализатор русскоязычных документов моделью LSTM и генератором
ответов по шаблону. Установить, как способ обучения LSTM влияет на выбор документа,
из которого генератор берёт цитату.

# 2. Задачи

1. Реализовать LSTM-кодировщик с двумя способами обучения — восстановлением последовательности и поиском связанных фрагментов.
2. Построить шаблон ответа с проверяемым источником и обработать случай пустой выдачи.
3. Сопоставить LSA, Word2Vec, CNN и варианты LSTM на общей коллекции по качеству поиска и выбору первого документа.
4. Проверить генератор на пользовательских данных и разобрать случаи ошибочного выбора источника.

# 3. Ход работы

## 3.1. Коллекция и условия сравнения

Использована коллекция RIA News Retrieval [1]. Из неё отобраны 500 запросов с одной
размеченной релевантной статьёй на запрос. Эти статьи и фоновые документы составили
поисковую коллекцию из 10 000 статей. При отборе зафиксирован seed 42. Модели
обучались на текстах статей. Запросы и разметка использовались при формировании
оценочной коллекции и подсчёте метрик.

Для всех методов применены нормализация Unicode NFC,
приведение к нижнему регистру, замена «ё» на «е», токенизация, русский стемминг
Snowball и удаление стоп-слов. После обработки корпус содержал 1 168 263 токена.
При поиске документы ранжировались по косинусному сходству с запросом.

Из работы №4 использованы три анализатора. LSA проецирует TF-IDF-вектор текста
в пространство признаков с помощью усечённого SVD. Word2Vec вычисляет среднее
векторов слов с весами TF-IDF. CNN выделяет признаки последовательности свёрткой
и выбирает максимальную активацию каждого фильтра. Команды подготовки данных,
обучения и оценки приведены в [инструкции к анализатору](../semantic-analyzer/README.md#подготовка-и-обучение-на-риа).

## 3.2. Два способа обучения LSTM

**Восстановление последовательности (`--seq2seq`).** Кодировщик LSTM читает
префикс документа. Его последнее скрытое состояние задаёт вектор фиксированной
размерности. Такая схема передачи последовательности через вектор используется
в архитектуре encoder–decoder [2]. В работе целевая последовательность совпадает
со входной. На каждом шаге декодер LSTM получает копию вектора и предсказывает
исходный токен на соответствующей позиции. Кросс-энтропия учитывает только
известные токены. Для поиска используется вектор кодировщика.

**Поисковое обучение (режим по умолчанию).** Одна статья даёт два фрагмента разной длины, которые образуют положительную пару. Остальные статьи пакета дают
отрицательные примеры. Принцип обучения на фрагментах одного документа описан
в работе DeCLUTR [3]. Здесь оба фрагмента обрабатывает один LSTM-кодировщик.
Вектор фрагмента равен среднему его скрытых состояний по позициям без заполнения.
Симметричная функция потерь NT-Xent с температурой 0,1 поощряет высокий косинус
между векторами положительной пары относительно остальных фрагментов пакета [4].

Начальные векторы слов поисковой LSTM получены за пять эпох skip-gram с окном 5
на текстах этой же коллекции. Затем таблица слов и кодировщик обучались совместно.
Словарь строился по полным статьям, а у автокодировщика — по префиксам. При поиске
каждая LSTM обрабатывала первые токены запроса и документа в пределах своей длины входа.

| Параметр | LSTM seq2seq | Поисковая LSTM, компактная | Поисковая LSTM, основная |
|---|---:|---:|---:|
| Число терминов в словаре | 2 000 | 2 000 | 29 732 |
| Максимальная длина входа, токенов | 32 | 32 | 96 |
| Размер вектора слова | 24 | 24 | 64 |
| Размер скрытого состояния | 32 | 32 | 64 |
| Эпохи обучения LSTM | 3 | 3 | 4 |
| Скорость обучения Adam | 0,003 | 0,003 | 0,001 |

Во всех трёх случаях пакет содержал до 32 документов, минимальная частота
термина составляла 2. Компактная модель позволяет сравнить два способа обучения
при одинаковых размерностях, длине входа и числе эпох LSTM. При этом менялись
также инициализация векторов слов, состав словаря и способ получения вектора текста.

## 3.3. Как из выдачи получается ответ

Команда `generate` передаёт запрос выбранному анализатору. При непустой выдаче
генератор берёт первый документ, указывает его заголовок и ID и цитирует начало
текста. Для документа без заголовка источником служит ID. Длина исходного
фрагмента ограничена 180 символами. При обрезке шаблон добавляет многоточие.
Для пустой выдачи предусмотрен отдельный шаблон. Один и тот же генератор работает
со всеми четырьмя анализаторами. Декодер seq2seq используется на этапе обучения LSTM.

Проверка выполнена на пользовательском CSV из шести документов о Java, PostgreSQL
и Docker. Заголовки в CSV отсутствуют. На запрос «Docker контейнер» сохранённая
модель LSTM seq2seq поставила первой строку `container-a`.

> По запросу «Docker контейнер» первым найден документ «container-a». В нём сказано: «Docker запускает контейнер приложения».

Цитата соответствует полю `text` строки `container-a`. Для запроса без известных
слов та же модель вернула пустую выдачу, и генератор применил второй шаблон.

> По запросу «абракадабравыв» документы не найдены.

[Пользовательский CSV и команды проверки](../semantic-analyzer/README.md#пользовательские-данные) позволяют повторить оба примера.

## 3.4. Качество поиска и выбор источника

Для каждого запроса сохранено до десяти ID в порядке выдачи. При одной размеченной статье
Recall@5 равен доле запросов, для которых эта статья вошла в первую пятёрку.
Для MRR@10 вклад запроса равен обратному рангу статьи в десятке или нулю, если
статья пропущена. Обе метрики усреднены по всем 500 запросам, включая пустые выдачи.
Отдельно подсчитано число попаданий на первое место. Именно этот документ
выбирает шаблон.

| Анализатор | На 1-м месте, из 500 | В топ-5, из 500 | Recall@5 | MRR@10 |
|---|---:|---:|---:|---:|
| LSA | 88 | 152 | 0,304 | 0,231521 |
| Word2Vec | 278 | 389 | 0,778 | 0,649069 |
| CNN | 13 | 48 | 0,096 | 0,055890 |
| LSTM seq2seq | 1 | 1 | 0,002 | 0,002000 |
| Поисковая LSTM, компактная | 67 | 126 | 0,252 | 0,186744 |
| Поисковая LSTM, основная | 193 | 297 | 0,594 | 0,479976 |

Кросс-энтропия автокодировщика на фиксированном обучающем пакете снизилась
с 7,600 до 6,694 на известный токен. Однако по 494 запросам модель выдала
документы и пропустила размеченную статью в десятке. Ещё пять запросов
не содержали известных слов. Таким образом, основной источник промахов в этом
опыте — положение статьи в выдаче. Обучение восстановлению токенов само по себе
не обеспечило близости запроса и соответствующей статьи.

По сохранённой выдаче основная поисковая LSTM выбрала бы размеченную статью
источником цитаты в 38,6% запросов (193 из 500). Ещё в 104 случаях эта статья
занимала места со второго по пятое. Она была видна в списке, но в шаблон попал бы
другой документ. В разметке указан единственный положительный ID, поэтому другие
тематически подходящие статьи также могли остаться без зачёта.
У Word2Vec доля совпадений источника с разметкой составила 55,6% (278 из 500).

Например, по запросу «украина обжаловала решение суда по иску минобороны россии»
основная поисковая LSTM поставила размеченную статью `364354` первой. Автокодировщик
выбрал `8838`. По запросу «день в фотографиях, 17 июля 2012 года» обе модели
пропустили статью `346305` в первой десятке. Даже точная цитата из выбранного
источника в таком случае может относиться к другому событию.

# 4. Выводы

При одинаковых размерах представлений компактная поисковая LSTM увеличила число
попаданий в топ-5 с 1 до 126 по сравнению с seq2seq. Расширенная конфигурация
достигла 297 попаданий и заняла второе место после Word2Vec. Эксперимент оценивает
сочетания параметров. Вклад каждого изменения по отдельности не измерялся.
Те же 500 запросов уже использовались в работе №4. Выводы относятся к поиску
по данной коллекции при выбранных параметрах.

Шаблон позволяет проверить происхождение текста по ID и цитате. В ответ попадает
только начало первого документа. Даже при
верно выбранной статье нужные сведения могут оказаться дальше по тексту. Разметка
указывает релевантную статью целиком, поэтому по ней можно оценить выбор источника.
Для оценки полноты ответа потребовалась бы отдельная разметка фрагментов.
